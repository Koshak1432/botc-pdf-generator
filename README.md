# Генератор памяток BOTC на TypeScript

Генератор PDF-памяток для «Крови на Часовой башне» из JSON сценария.
Он подставляет названия и описания ролей из каталога, располагает их в SAO-порядке и создаёт страницы A4:
сначала памятку с ролями, затем ночной порядок, особые правила Бутлегера, сглазы и таблицу количества игроков.

## Быстрый запуск

Если зависимости и Chromium уже установлены, из папки проекта достаточно выполнить одну команду:

```powershell
npm.cmd run generate -- "./scripts_json/teensyville/The-nightmare-king.json"
```

Результат появится здесь:

```text
output/pdf/The Nightmare King.pdf
```

Имя PDF берётся из `_meta.name` внутри JSON, поэтому оно может отличаться от имени исходного файла.
Если названия в JSON нет, используется имя файла сценария. Недопустимые символы в имени заменяются автоматически.
Папки для результата создаются сами. Повторный запуск с тем же выходным путём перезаписывает PDF.
В конце команда выводит путь, число страниц и размер файла.

Разделитель `--` передаёт следующие аргументы генератору через npm.
`npm.cmd run generate` автоматически запускает сборку перед генерацией: отдельно выполнять `build` не нужно.

Все примеры ниже рассчитаны на запуск из корня проекта в PowerShell:

```powershell
cd C:\botc-pdf-generator
```

В Windows можно использовать `/` или `\` в путях. Папка называется `scripts_json`: экранировать подчёркивание не нужно.
Пути с пробелами заключайте в кавычки. На Linux и macOS используйте `npm` вместо `npm.cmd`
и соблюдайте регистр имени файла: в репозитории это `The-nightmare-king.json`.

## Установка при первом запуске

Требуются Node.js 20.11 или новее и npm.

```powershell
node --version
npm.cmd --version
npm.cmd ci
npm.cmd run install:browser
npm.cmd run generate -- "./scripts_json/teensyville/The-nightmare-king.json"
```

`npm.cmd ci` устанавливает версии зависимостей из `package-lock.json`.
Chromium нужен для печати HTML в PDF; его достаточно установить один раз для используемой версии Playwright.
Установка зависимостей и браузера требует доступа к сети.
После изменения `package-lock.json` повторите `npm.cmd ci`; при обновлении Playwright может потребоваться переустановка Chromium.

Если вы меняете зависимости проекта, используйте `npm.cmd install`, чтобы обновить и `package-lock.json`.
Если PowerShell запрещает запуск `npm.ps1`, используйте показанный в примерах `npm.cmd`.

## Что происходит при генерации

1. npm запускает `pregenerate`: TypeScript компилируется в `dist/`, туда копируются CSS, шрифты и скрипты расчёта размеров.
2. Генератор читает JSON сценария, каталог ролей и справочники ночного порядка и сглазов.
3. Проверяются метаданные, идентификаторы ролей и форматирование. Роли из сценария сопоставляются с каталогом.
4. Выбираются переводы, применяются переопределения оформления, роли сортируются по SAO и распределяются по страницам.
5. Загружаются изображения. Встроенные локальные иконки и шрифты включаются в HTML, затем — в PDF.
6. Формируется ночная страница с активными ролями, правилами Бутлегера и только применимыми к сценарию сглазами.
7. Chromium дожидается шрифтов и изображений, подбирает размеры иконок и таблицы игроков и проверяет размещение.
8. Сохраняется PDF. Если запрошены `--html` или `--memo-json`, эти файлы записываются ещё до печати PDF.

По умолчанию язык — русский, на странице ролей допускается максимум 25 карточек.
Каждая команда ролей оформляется отдельной секцией с двумя колонками. Обычно получается две страницы:
роли и ночной порядок. При большем количестве карточек сначала идут несколько страниц ролей, затем ночная страница.
Рекомендованные Странники автоматически не добавляются.

Названия ролей печатаются размером 18 pt, описания — 14,5 pt.
Если места не хватает, иконки уменьшаются с 19 до минимум 12 мм, а размер шрифта сохраняется.
Если даже минимальные иконки не помогают, генератор сообщает об ошибке размещения.

## Варианты запуска

### Обычная генерация

```powershell
npm.cmd run generate -- "./scripts_json/teensyville/The-nightmare-king.json"
npm.cmd run generate -- "./scripts_json/A Grimm Chorus.json"
npm.cmd run generate -- "./examples/a-grimm-chorus.json"
```

Каждая строка — самостоятельный пример. Первый аргумент после `--` — путь к JSON сценария.
Для обычной русской памятки других параметров не требуется.

### Свои имя файла и папка результата

```powershell
npm.cmd run generate -- "./scripts_json/teensyville/The-nightmare-king.json" --out "./output/pdf/Моя памятка.pdf"
```

### PDF вместе с HTML-превью и промежуточной моделью

```powershell
npm.cmd run generate -- "./scripts_json/teensyville/The-nightmare-king.json" `
  --out "./output/pdf/nightmare.pdf" `
  --html "./output/preview/nightmare.html" `
  --memo-json "./output/model/nightmare.json"
```

HTML можно открыть в браузере. Он содержит оформление и скрипты подбора размеров.
Промежуточный JSON содержит разрешённые роли, форматированный текст, ночной порядок, сглазы и данные изображений.
Он нужен для проверки результата компиляции; это не входной JSON сценария.
Эти файлы могут сохраниться даже при последующей ошибке печати PDF.

Символ обратной кавычки в конце строки — перенос команды PowerShell. После него не должно быть пробелов.
Любую такую команду можно записать одной строкой без обратных кавычек.

### Язык, подпись под заголовком и количество ролей на странице

```powershell
npm.cmd run generate -- "./scripts_json/teensyville/The-nightmare-king.json" --locale en
npm.cmd run generate -- "./scripts_json/teensyville/The-nightmare-king.json" --subtitle "Партия в пятницу"
npm.cmd run generate -- "./scripts_json/A Grimm Chorus.json" --cards-per-page 20
```

`--locale` выбирает имеющийся перевод, а не переводит текст заново.
Например, для `ru-RU` может использоваться `ru`; если перевода роли нет, берётся её канонический текст.
Правила Бутлегера остаются на языке, на котором написаны в JSON.

`--cards-per-page` задаёт положительное целое число — верхний предел карточек на одной странице ролей.
Меньшее число распределяет роли по большему количеству страниц. Большее число позволяет попытаться собрать их на одном листе,
но не отменяет минимальный размер иконок и проверку размещения. Ночной порядок этим параметром не разбивается.

### Другой каталог или переопределение оформления

```powershell
npm.cmd run generate -- "./examples/a-grimm-chorus.json" --catalog "./examples/a-grimm-chorus-roles.ru.json"
npm.cmd run generate -- "./examples/a-grimm-chorus.json" --overrides "./examples/formatting.json"
```

`--catalog` заменяет каталог ролей. Справочники ночного порядка и сглазов остаются встроенными.
`--overrides` меняет названия, описания и изображения выбранных ролей без изменения SAO-порядка.
В готовом `examples/formatting.json` текст для Генерала написан по-английски: он заменит русский текст этой роли.

### Изображения и кэш

```powershell
npm.cmd run generate -- "./scripts_json/teensyville/The-nightmare-king.json" --assets-dir "./assets/roles"
npm.cmd run generate -- "./scripts_json/teensyville/The-nightmare-king.json" --cache-dir "./.cache/custom-assets"
npm.cmd run generate -- "./scripts_json/teensyville/The-nightmare-king.json" --no-fetch-assets
```

`--assets-dir` выбирает папку локальных изображений, названных по ID роли.
Найденный в ней файл имеет приоритет перед изображением из каталога или `--overrides`.
Если локального файла нет, используется ссылка из данных роли.
Удалённые изображения при обычном запуске скачиваются и кэшируются в `--cache-dir`.

`--no-fetch-assets` отключает скачивание и встраивание удалённых изображений на этапе подготовки HTML.
Сами внешние ссылки при этом могут остаться в HTML, и Chromium может обратиться к ним при печати.
Для работы без сети нужны локальные или уже встроенные изображения, включая логотип сценария.
Для стандартных ролей полный набор иконок уже есть в `assets/roles`.

### Частичный результат при ошибках сценария

```powershell
npm.cmd run generate -- "./scripts_json/teensyville/The-nightmare-king.json" --allow-partial
```

Этот флаг разрешает продолжить генерацию из частичной модели, например пропустить неизвестную роль.
Ошибки остаются в выводе команды, а результат может содержать не все роли сценария.
Флаг не исправляет невалидный JSON, не отменяет ошибки файла переопределений и не отключает проверку размещения на странице.

### Повторные запуски без сборки каждый раз

```powershell
npm.cmd run build
node ./dist/cli/index.js generate "./scripts_json/teensyville/The-nightmare-king.json"
node ./dist/cli/index.js generate "./scripts_json/A Grimm Chorus.json" --out "./output/pdf/chorus.pdf"
```

Прямой запуск через `node` использует уже собранный `dist/` и не запускает сборку автоматически.
После изменений в `src/`, включая CSS и скрипты расчёта размеров, сначала повторите `npm.cmd run build`.
В этом варианте разделитель npm `--` не нужен: параметры указываются сразу после пути сценария.

При желании можно зарегистрировать локальную команду `botc-pdf`:

```powershell
npm.cmd run build
npm.cmd link
botc-pdf generate "./scripts_json/teensyville/The-nightmare-king.json"
```

Для обычной работы регистрация команды не требуется. Все параметры `generate` одинаковы во всех вариантах запуска.

### Генерация всех сценариев из папки

Встроенного пакетного режима нет. В PowerShell можно собрать проект один раз и запустить CLI для каждого JSON:

```powershell
npm.cmd run build
if ($LASTEXITCODE -ne 0) { throw "Не удалось собрать проект." }

Get-ChildItem -LiteralPath "./scripts_json" -Filter "*.json" -File -Recurse | ForEach-Object {
  node ./dist/cli/index.js generate $_.FullName
  if ($LASTEXITCODE -ne 0) { throw "Ошибка генерации: $($_.FullName)" }
}
```

`-Recurse` включает вложенную папку `teensyville`. Для обработки только этой папки замените путь на `./scripts_json/teensyville`.
Цикл останавливается на первой ошибке. Файлы сохраняются в `output/pdf/` по названиям сценариев.
Сценарии с одинаковым `_meta.name` получат один выходной путь; для разных результатов задавайте разные `--out`.

### Справка и версия

```powershell
npm.cmd run generate -- --help
node ./dist/cli/index.js --help
node ./dist/cli/index.js --version
```

Первый вариант автоматически выполняет сборку, остальные используют существующий `dist/`.

## Все параметры команды generate

```text
botc-pdf generate [параметры] <script.json>
```

Параметры можно комбинировать в одной команде.

| Параметр                 | Действие и значение по умолчанию                                        |
| ------------------------ | ----------------------------------------------------------------------- |
| `<script.json>`          | Обязательный путь к JSON сценария.                                      |
| `--catalog <file>`, `-c` | Каталог ролей. По умолчанию `catalog/roles.ru.json`.                    |
| `--out <file>`, `-o`     | Выходной PDF. По умолчанию `output/pdf/<название сценария>.pdf`.        |
| `--locale <tag>`, `-l`   | Язык текста. По умолчанию `ru`.                                         |
| `--overrides <file>`     | JSON с переопределениями оформления. По умолчанию не применяется.       |
| `--assets-dir <dir>`     | Папка локальных иконок. По умолчанию `assets/roles`.                    |
| `--cache-dir <dir>`      | Кэш скачанных изображений. По умолчанию `.cache/assets`.                |
| `--no-fetch-assets`      | Не скачивать удалённые изображения при подготовке HTML.                 |
| `--html <file>`          | Дополнительно сохранить HTML-превью по указанному пути.                 |
| `--memo-json <file>`     | Дополнительно сохранить промежуточную модель памятки.                   |
| `--cards-per-page <n>`   | Максимум ролей на странице. По умолчанию `25`.                          |
| `--subtitle <text>`      | Подпись под заголовком на страницах ролей. По умолчанию отсутствует.    |
| `--allow-partial`        | Разрешить частичную модель при ошибках сценария. По умолчанию выключен. |
| `--help`, `-h`           | Показать справку по команде.                                            |

`--version` / `-V` относится к основной команде: `node ./dist/cli/index.js --version`.
У CLI одна рабочая подкоманда — `generate`; отдельного режима «только HTML» или отключения ночной страницы нет.

Пути сценария, параметров CLI и результатов считаются относительно текущей папки терминала.
Встроенные каталоги и ресурсы находятся относительно установки проекта.
Относительные ссылки на изображения внутри JSON, в том числе в переопределениях, считаются относительно папки сценария.

## Формат сценария и каталог

Сценарий — JSON-массив. Он может содержать метаданные, строки с ID ролей и объекты с одним полем `id`:

```json
[
  { "id": "_meta", "name": "Мой сценарий", "author": "Автор" },
  "washerwoman",
  { "id": "soldier" }
]
```

`_meta.name` задаёт заголовок и имя выходного PDF. Для присутствующего объекта `_meta` это обязательная непустая строка.
Сам объект `_meta` необязателен. `author` сохраняется в модели, но на памятке не печатается; `logo` задаёт логотип.
Полная встроенная роль задаётся объектом с `id`, `name`, `team`, `ability` и при необходимости другими полями,
например `image`, `translations` или `saoGroup`.
Объект с дополнительными полями рассматривается как полное описание роли, а не как частичное переопределение каталога.

В `catalog/roles.ru.json` находятся 181 официальная роль с русскими названиями и описаниями.
Поле `flavor` удалено, технические поля и канонические английские названия и способности сохранены.
Перевод хранится в `translations.ru`. Обычная генерация использует готовые локальные данные, без обращения к переводчику или вики.

## Форматирование и переопределения

Поддерживаются `[b]...[/b]` и `[color=#RRGGBB]...[/color]`.
Текст экранируется; произвольный HTML не выполняется. Некорректная разметка может давать диагностические ошибки.

Файл для `--overrides` — объект, ключами которого служат ID ролей. Поля внутри необязательны:

```json
{
  "general": {
    "nameMarkup": "[b]Генерал[/b]",
    "abilityMarkup": "[b]Каждую ночь:[/b] вы узнаёте, кто ближе к победе: [color=#146BB3]добро[/color] или зло.",
    "image": "images/general.webp"
  }
}
```

Для изменения только текста удалите поле `image`. Для замены изображения удобнее передать свою папку через `--assets-dir`.
Переопределения влияют на отображение, но не меняют канонические данные для сортировки.

## Иконки и размеры страниц

В `assets/roles` находятся 181 иконка WebP. Допустимы также файлы `<id>.png`, `<id>.jpg`, `<id>.jpeg` и `<id>.svg`.
При наличии нескольких файлов для роли используется первый в порядке WebP, PNG, JPG, JPEG, SVG.
Если изображение не удалось получить, его место остаётся пустым, без буквенной подложки.

На страницах ролей подбор размеров выполняется отдельно после загрузки шрифтов и изображений.
Уменьшаются иконка, ширина места под неё и минимальная высота карточки. Текст получает больше ширины без изменения шрифта.
В HTML-превью размеры пересчитываются при изменении содержимого и перед печатью.
Иконки ночного порядка и сглазов этот расчёт не затрагивает.

Настройки в `:root` файла `src/render/print.css`:

```css
--role-name-font-size: 18pt;
--role-description-font-size: 14.5pt;
--role-icon-size: 19mm;
--role-icon-min-size: 12mm;
```

Минимальный размер должен быть положительным и не превышать исходный.
Если содержимое не помещается даже при минимуме, уменьшите `--cards-per-page`, чтобы добавить страницы ролей.
После правки CSS используйте обычный запуск через npm или пересоберите `dist/` вручную.

## Ночная страница, Бутлегер и сглазы

Ночная страница всегда следует за страницами ролей.
Первая ночь выводится слева, последующие ночи — справа; порядок берётся из `catalog/nightsheet.json`.
В центре печатаются сглазы из `catalog/jinxes.ru.json`, только если обе роли входят в сценарий.

Если в сценарии есть `bootlegger`, его особые правила читаются из массива `_meta.bootlegger`:

```json
[
  {
    "id": "_meta",
    "name": "Сценарий с особыми правилами",
    "bootlegger": [
      "Первое особое правило сценария.",
      "[b]Второе правило[/b] выводится отдельным абзацем."
    ]
  },
  { "id": "soldier" },
  { "id": "bootlegger" }
]
```

Все правила выводятся в исходном порядке и на исходном языке под заголовком «Бутлегер», над сглазами.
Карточка Бутлегера убирается со страницы ролей. Если собственных правил нет, выводится его обычное описание.
Если роли нет, её заголовок и отступ не появляются, даже при заполненном `_meta.bootlegger`.
В программном API при модели без ночной страницы правила сохраняются в карточке Бутлегера.

Внизу ночной страницы находится таблица из `assets/night/player-counts.jpg`.
Её ширина по умолчанию — 140 мм, минимальная — 70 мм. Таблица уменьшается, если мешает ночному порядку, правилам или сглазам.
Учитываются также выступающие за строки иконки. Если читаемая таблица не помещается, HTML показывает пояснение, а PDF не создаётся.

Настройки в `.memo-page--night` файла `src/render/print.css`:

```css
--night-table-width: 140mm;
--night-table-min-width: 70mm;
--night-table-bottom: 5mm;
--night-table-gap-mm: 3;
```

Последний параметр — зазор до другого содержимого в миллиметрах, записанный без единицы измерения.

## Сортировка SAO

- Порядок команд: Горожане, Изгои, Приспешники, Демоны, Странники, Сказочные, Лорики.
- Позиции официальных ролей определяются закреплённым каталогом.
- Авторские роли вставляются по группе SAO, длине канонической способности, длине имени, английскому имени и ID.
- Для авторской роли можно явно задать `saoGroup`.
- Переводы и переопределения оформления не влияют на сортировку.

## Команды разработки и обслуживания

| Команда                                 | Назначение                                                      |
| --------------------------------------- | --------------------------------------------------------------- |
| `npm.cmd run generate -- <script.json>` | Собрать проект и сгенерировать PDF.                             |
| `npm.cmd run pregenerate`               | Сборка, автоматически вызываемая перед `generate`.              |
| `npm.cmd run build`                     | Скомпилировать TypeScript и скопировать ресурсы в `dist/`.      |
| `npm.cmd run install:browser`           | Установить Chromium для Playwright.                             |
| `npm.cmd run typecheck`                 | Проверить типы без создания файлов сборки.                      |
| `npm.cmd test`                          | Запустить модульные, интеграционные и HTML-тесты.               |
| `npm.cmd run test:watch`                | Перезапускать тесты при изменении файлов.                       |
| `npm.cmd run test:pdf`                  | Запустить тесты реальной вёрстки и PDF в Chromium.              |
| `npm.cmd run format`                    | Переформатировать исходники, тесты, конфигурацию и README.      |
| `npm.cmd run format:check`              | Проверить форматирование без изменения файлов.                  |
| `npm.cmd run check`                     | Последовательно проверить форматирование, типы и обычные тесты. |
| `npm.cmd run assets:roles:check`        | Проверить наличие и корректность локальных иконок.              |
| `npm.cmd run assets:roles`              | Скачать недостающие иконки и проверить набор.                   |
| `npm.cmd run catalog:ru`                | Обновить русский каталог из внешних источников.                 |

`check` не запускает PDF-тесты; для них используется отдельная команда `test:pdf`.
Проверки не являются обязательным шагом перед каждым обычным запуском генерации.

Для повторного скачивания иконок:

```powershell
npm.cmd run assets:roles -- --force
```

Команда иконок также принимает `--catalog <file>`, `--out <dir>` и `--check`.
`assets:roles:check` уже передаёт `--check`; сочетать его с `--force` нельзя.
Проверка набора рассчитана на 181 официальную роль.

Обновление каталога — отдельная операция, которая обращается к внешним источникам:

```powershell
npm.cmd run catalog:ru
npm.cmd run catalog:ru -- --source "./tmp/roles.json" --out "./tmp/roles.updated.ru.json"
```

Во втором примере сначала подготовьте исходный `tmp/roles.json`.
`--source` заменяет источник официальных ролей, `--out` задаёт выходной файл; по умолчанию обновляется `catalog/roles.ru.json`.
Даже при локальном `--source` переводы и дополнительные данные запрашиваются по сети.
Для обычной генерации PDF обновлять каталог не требуется.

## Частые проблемы

| Ситуация                                 | Что сделать                                                                      |
| ---------------------------------------- | -------------------------------------------------------------------------------- |
| `node` или `npm.cmd` не найдены          | Установить Node.js с npm и открыть терминал заново.                              |
| PowerShell запрещает `npm.ps1`           | Использовать `npm.cmd`.                                                          |
| Нет `dist/cli/index.js`                  | Выполнить `npm.cmd run build` или запускать через `npm.cmd run generate -- ...`. |
| Chromium не установлен                   | Выполнить `npm.cmd run install:browser`.                                         |
| JSON не найден                           | Проверить текущую папку, путь, кавычки и регистр имени файла.                    |
| Роль не найдена в каталоге               | Проверить ID, передать другой каталог или полное описание авторской роли.        |
| Текст ролей не помещается                | Уменьшить `--cards-per-page`; иконки уже подбираются до заданного минимума.      |
| Не помещается таблица на ночной странице | Проверить объём правил и сглазов и настройки ночной вёрстки в `print.css`.       |
| После правки CSS результат прежний       | Пересобрать проект; прямой запуск `node` не обновляет `dist/`.                   |

При остановке из-за ошибки CLI завершает работу с ненулевым кодом. Предупреждения сами по себе не останавливают генерацию.
Папки `output/`, `tmp/`, `.cache/` и файлы PDF исключены из Git через `.gitignore`.

## Структура проекта

```text
scripts_json/        готовые сценарии, включая teensyville/
examples/            A Grimm Chorus и пример переопределений оформления
catalog/             роли, переводы, ночной порядок и сглазы
assets/roles/        локальные иконки ролей
assets/night/        маркеры ночного порядка и таблица количества игроков
src/core/            импорт, локализация, SAO и модель памятки
src/render/          изображения, React-шаблон, CSS, подбор размеров и PDF
src/render/fonts/    локальные шрифты
src/cli/             командная строка
scripts/             сборка ресурсов и обновление каталогов и иконок
tests/               модульные, интеграционные и PDF-тесты
dist/                скомпилированный код; создаётся при сборке
output/              PDF и другие результаты генерации
tmp/                 временные файлы и результаты проверок
.cache/              кэш скачанных изображений
```

Шрифт `Dumbledor 3 Thin` хранится локально и встраивается в PDF как подмножество TrueType.
Файл шрифта не содержит лицензионных условий; перед его публичным или коммерческим распространением нужно подтвердить право на это.
